# 超级管理员初始设置指南

## 概述

本文档介绍如何在系统首次部署时通过环境变量设置初始超级管理员账户。

## 环境变量配置

在系统首次部署前，需要在 `.env` 文件中配置以下环境变量：

```bash
# 初始超级管理员配置
INITIAL_SUPER_ADMIN_USERNAME=admin
INITIAL_SUPER_ADMIN_EMAIL=admin@yourcompany.com
INITIAL_SUPER_ADMIN_PASSWORD=YourSecurePassword123!
```

### 配置说明

| 环境变量 | 必填 | 说明 | 示例 |
|---------|------|------|------|
| `INITIAL_SUPER_ADMIN_USERNAME` | 是 | 超级管理员用户名 | `admin` |
| `INITIAL_SUPER_ADMIN_EMAIL` | 是 | 超级管理员邮箱 | `admin@yourcompany.com` |
| `INITIAL_SUPER_ADMIN_PASSWORD` | 是 | 超级管理员密码 | `YourSecurePassword123!` |

### 密码要求

- 最小长度：12 个字符
- 必须包含：大写字母、小写字母、数字、特殊字符
- 建议：使用密码生成器生成强密码

## 部署流程

### 1. 准备环境变量文件

```bash
# 复制示例环境变量文件
cp .env.example .env

# 编辑 .env 文件，设置初始超级管理员信息
vim .env
```

### 2. 启动系统

```bash
# 安装依赖
npm install

# 启动开发服务器
npm run dev

# 或启动生产服务器
npm start
```

### 3. 验证初始化

系统启动后，检查日志输出：

```
========================================
初始超级管理员创建成功！
用户名: admin
邮箱: admin@yourcompany.com
========================================
重要提示：
1. 请立即登录并修改初始密码
2. 请启用双重认证以增强安全性
3. 请创建其他管理员账户作为备份
4. 建议删除或修改环境变量中的密码
========================================
```

## 首次登录后的操作

### 1. 修改初始密码

1. 使用环境变量中设置的凭据登录系统
2. 进入个人设置页面
3. 修改密码为新的强密码

### 2. 启用双重认证

1. 进入安全设置页面
2. 启用双重认证（TOTP）
3. 使用 Google Authenticator 或类似应用扫描二维码
4. 保存恢复码到安全位置

### 3. 创建备份管理员账户

1. 进入管理员管理页面
2. 邀请另一个超级管理员作为备份
3. 确保至少有两个活跃的超级管理员账户

### 4. 清理环境变量

出于安全考虑，建议在首次登录后：

1. 删除或注释掉 `.env` 文件中的密码环境变量
2. 重启应用服务

```bash
# 编辑 .env 文件，注释掉密码
# INITIAL_SUPER_ADMIN_PASSWORD=YourSecurePassword123!
```

## 安全最佳实践

### 生产环境部署

1. **使用强密码**：使用密码生成器生成至少 16 位的随机密码
2. **限制访问**：将初始超级管理员的邮箱设置为组织内部邮箱
3. **及时修改**：首次登录后立即修改密码
4. **启用 2FA**：强制启用双重认证
5. **创建备份**：创建至少一个备份超级管理员账户
6. **清理痕迹**：部署完成后删除环境变量中的密码

### 密码管理

```bash
# 使用 openssl 生成强密码
openssl rand -base64 24

# 或使用 pwgen（如果已安装）
pwgen -s 24 1
```

### 环境变量保护

1. **文件权限**：确保 `.env` 文件权限为 600
   ```bash
   chmod 600 .env
   ```

2. **版本控制**：确保 `.env` 文件已添加到 `.gitignore`
   ```bash
   echo ".env" >> .gitignore
   ```

3. **密钥管理**：考虑使用密钥管理服务（如 AWS Secrets Manager、Azure Key Vault）

## 故障排除

### 问题：超级管理员未创建

**症状**：系统启动后没有显示超级管理员创建成功的日志

**可能原因**：
1. 环境变量未正确设置
2. 数据库连接失败
3. 已存在超级管理员账户

**解决方案**：
1. 检查 `.env` 文件是否正确加载
2. 检查数据库连接是否正常
3. 检查数据库中是否已有超级管理员账户

### 问题：密码验证失败

**症状**：提示密码长度不足或格式不正确

**解决方案**：
确保密码满足以下要求：
- 至少 12 个字符
- 包含大写字母
- 包含小写字母
- 包含数字
- 包含特殊字符

### 问题：邮箱已被使用

**症状**：提示邮箱已被注册

**解决方案**：
1. 使用其他邮箱地址
2. 或删除现有用户后重新部署

## 后续维护

### 定期审查

- **每月**：审查超级管理员账户活动
- **每季度**：更新超级管理员密码
- **每半年**：审查管理员权限分配

### 备份策略

- 始终保持至少两个活跃的超级管理员账户
- 定期备份超级管理员账户信息
- 建立超级管理员账户恢复流程
