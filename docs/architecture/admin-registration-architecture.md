# 管理员注册方案设计

## 1. 概述

本文档设计了一个安全、完整的管理员注册方案，用于 SkillHub 平台的管理员账户创建和管理。该方案采用邀请制注册模式，确保只有经过授权的用户才能成为管理员，同时提供多层次的安全保障措施。

## 2. 设计目标

- **安全性**：确保只有授权用户能成为管理员
- **可审计性**：所有管理员操作都有详细的审计日志
- **可扩展性**：支持多管理员场景
- **用户友好**：提供清晰的注册流程
- **合规性**：符合现代安全标准和最佳实践

## 3. 核心功能

### 3.1 管理员邀请系统

- **邀请生成**：现有管理员可以生成带有过期时间的邀请链接
- **邀请验证**：通过唯一的邀请码验证邀请的有效性
- **权限控制**：邀请时可指定管理员权限级别

### 3.2 安全注册流程

- **邮箱验证**：强制邮箱验证，确保邮箱真实性
- **密码策略**：强密码要求，包括长度、复杂度等
- **双重认证**：可选的 TOTP 双重认证
- **IP 限制**：可配置的 IP 访问限制

### 3.3 管理员权限管理

- **角色分级**：
  - 超级管理员（super_admin）：拥有所有权限
  - 普通管理员（admin）：拥有大部分管理权限
  - 审计管理员（audit_admin）：只能查看审计日志

### 3.4 审计与监控

- **操作审计**：记录所有管理员操作
- **登录监控**：监控异常登录行为
- **权限变更**：记录所有权限变更

## 4. 技术实现

### 4.1 数据模型

#### 4.1.1 管理员邀请模型

```typescript
interface AdminInvitation {
```

### 4.2 API 设计

#### 4.2.1 管理员邀请 API

| 端点 | 方法 | 描述 | 权限 |
|------|------|------|------|
| `/api/admin/invitations` | POST | 创建管理员邀请 | super_admin |
| `/api/admin/invitations` | GET | 获取邀请列表 | super_admin, admin |
| `/api/admin/invitations/:id` | DELETE | 取消邀请 | super_admin |
| `/api/auth/register/admin` | POST | 通过邀请注册管理员 | 公开（需要邀请码） |

#### 4.2.2 管理员管理 API

| 端点 | 方法 | 描述 | 权限 |
|------|------|------|------|
| `/api/admin/users` | GET | 获取用户列表 | super_admin, admin |
| `/api/admin/users/:id/role` | PUT | 更新用户角色 | super_admin |
| `/api/admin/users/:id/permissions` | PUT | 更新管理员权限 | super_admin |
| `/api/admin/users/:id/two-factor` | POST | 启用/禁用双重认证 | super_admin |

#### 4.2.3 安全 API

| 端点 | 方法 | 描述 | 权限 |
|------|------|------|------|
| `/api/auth/two-factor/verify` | POST | 验证双重认证码 | 所有用户 |
| `/api/auth/password/change` | POST | 修改密码 | 所有用户 |
| `/api/auth/password/expire` | POST | 强制密码过期 | super_admin |

### 4.3 安全措施

1. **邀请码安全**：
   - 使用加密随机生成的邀请码
   - 设置合理的过期时间（默认 7 天）
   - 邀请码只能使用一次

2. **密码安全**：
   - 最小长度 12 位
   - 要求包含大小写字母、数字和特殊字符
   - 密码哈希使用 bcrypt（成本因子 12）
   - 密码每 90 天强制更新

3. **双重认证**：
   - 支持 TOTP（基于时间的一次性密码）
   - 为管理员强制启用
   - 提供备用恢复码

4. **访问控制**：
   - 基于角色的访问控制（RBAC）
   - 细粒度的权限管理
   - 敏感操作需要二次验证

5. **审计与监控**：
   - 记录所有管理员操作
   - 监控异常登录行为
   - 定期安全审计

## 5. 注册流程

### 5.1 邀请流程

1. 现有超级管理员登录系统
2. 进入管理员管理页面
3. 点击"邀请管理员"
4. 填写被邀请人邮箱、角色和权限
5. 系统生成唯一邀请链接并发送到被邀请人邮箱

### 5.2 注册流程

1. 被邀请人点击邮箱中的邀请链接
2. 系统验证邀请码的有效性
3. 被邀请人填写注册信息（用户名、密码等）
4. 系统发送邮箱验证邮件
5. 被邀请人点击验证链接激活账户
6. 系统引导设置双重认证
7. 注册完成，自动登录系统

## 6. 安全考虑

1. **防止邀请链接泄露**：
   - 邀请链接包含一次性使用的加密邀请码
   - 邀请链接有过期时间
   - 邀请状态实时更新

2. **防止暴力破解**：
   - 登录尝试限制（5 次失败后锁定 15 分钟）
   - 验证码机制
   - IP 封禁

3. **防止权限提升**：
   - 权限变更需要超级管理员批准
   - 权限变更有详细审计日志
   - 定期权限审查

4. **数据保护**：
   - 敏感数据加密存储
   - 传输数据使用 HTTPS
   - 定期数据备份

## 7. 部署与维护

### 7.1 初始设置

1. 系统首次部署时，创建默认超级管理员账户
2. 设置安全的初始密码
3. 配置邮件服务
4. 配置安全设置

### 7.2 定期维护

1. 定期审查管理员列表
2. 定期更新安全设置
3. 定期检查审计日志
4. 定期进行安全漏洞扫描

## 8. 结论

本设计方案提供了一个安全、完整的管理员注册系统，通过邀请制、多重验证和细粒度权限控制，确保只有授权用户才能成为管理员，同时提供了全面的安全保障措施，符合现代安全标准和最佳实践。

该方案不仅满足了当前的管理员注册需求，还为未来的系统扩展和安全升级提供了良好的基础。
